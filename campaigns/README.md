# Campaign programmes

Campaign programmes describe long-range work without creating executable plans.
They are TOML authorities, are always disarmed, and are projected into the
control panel alongside the separate source, recipe, qualification and queue
authorities.

## C80 four-source programme

`c80-four-source-n80-v1.toml` freezes the published four-source N80 frontier
from the mapping-the-tail research:

- 276 ranked candidates;
- 80.044856% cumulative popularity proxy at rank 276;
- 27 ten-candidate cohorts and one final six-candidate cohort;
- 37 qualified route profiles and six treatments in the current C width;
- at most 61,272 campaign executions if every candidate is accepted; and
- at most 4,416 compilation-only qualification cells.

The exact research rows are vendored as
`coverage/evidence/four-source-n80-v1.csv` and digest-bound by the programme.
This CSV is immutable evidence, not executable configuration. The programme
also pins the width authority and reusable qualification template by SHA-256.

The 276 rows are a popularity-priority frontier, not 276 already proven C
library families. It contains build tools, runtimes, umbrella projects and
possible aliases. Each row remains a candidate until a reviewed screen records
that it is a reusable native C/C++ library family in scope. An exclusion must
retain its reason. Extending beyond research rank 276 requires a new,
digest-bound candidate snapshot; it must never be improvised by the scheduler.

## Pipeline

Each cohort advances through the same gates:

1. candidate screen;
2. exact release pin and optional cache preparation;
3. command-free recipe authoring and review;
4. target/generation-edge recipe qualification;
5. digest-bound qualification seal;
6. measured time model;
7. short, chained, disarmed queue candidate;
8. full-path compile/Ghidra/publication canary;
9. explicit operator admission;
10. campaign execution;
11. scheduled machine validation; and
12. dry-run-first retention and worker-memory cleanup.

Source presence is not recipe readiness. Recipe resolution is not compilation
qualification. Qualification is not permission to arm. Generated queue chunks
remain disarmed until an operator reviews the exact identities and the
full-path canary passes.

Inspect the complete projection without downloading or executing anything:

```sh
uv run fidb-poc campaign-programme --project-root .
```

The Matrix page renders a compact funnel and one collapsed row per cohort.
Expanding a row shows every research candidate and its earliest unmet gate.

## Current overlays

The current `sources/c-top30-v1.toml` working set is a separate screened,
two-source calibration ranking. Its identities may overlap the four-source
frontier, but its ranks must not be substituted for research ranks. The
programme joins overlapping identities only to display current source, cache,
recipe, width-batch and qualification state.

Changing the candidate order, identity aliases, cohort boundaries, width or
qualification edge set requires a new reviewed authority and digest updates.
Rollback is additive: keep queues disarmed, revert the programme/UI commits,
and retain any source, build or ledger evidence created independently. The
programme itself creates no runtime artifacts.
